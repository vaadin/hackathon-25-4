# 06 AI

## What the assistant is for

The security team answers the same three questions all day, is this version safe, what does this advisory mean for this customer, what should we verdict next, and every answer already exists in the measured data. The assistant's job is retrieval with judgment attached, never judgment of its own: it reads the same `SecurityDataService` the screens read, and an answer it cannot ground in a tool result is an answer it must not give. The system prompt says so and the cassette tests hold it to that.

The assistant is an internal surface, inside the `SECURITY` area. A customer facing bot that answers security questions is a liability decision nobody asked this hackathon to take, and the decision is recorded here.

## Providers

- Default build: a mock `LLMProvider` with recorded cassettes: `src/main/resources/cassettes/` for what the running application replays and `src/test/resources/cassettes/` for exchanges only tests use, D-137. No key, no network, fully deterministic, and the whole test suite runs against it. A production run with no model does not offer the assistant at all, unless `securitystatus.assistant.recorded=true` asks for the cassettes, as the `it` profile does; the log says at startup which mode answers, D-236.
- `-Pai`, or any environment with `OPENAI_API_KEY`: `SpringAILLMProvider` over Spring AI's OpenAI starter; `securitystatus.assistant.live=false` forces the cassettes even with a model, and `securitystatus.assistant.recorded=true` offers the cassettes in a production build, D-236. One real provider, because a second wiring proves nothing this application asks.
- Request interception logs every prompt and tool call to the diagnostics view, which is the 25.3 request interception API doing real work: the team can read what the assistant actually asked.

## The chat assistant

`AIOrchestrator` with `AIMessageList` and `AIInput` in the panel on the right of the internal shell, opened by the Assistant button and shut on arrival, covering the page below 800 pixels, D-203, D-255, so it is present on every internal screen without owning any.

### Tools

Each tool is a thin reading of `SecurityDataService`, refuses through `ToolException` with a sentence the model can correct from, and returns compact JSON, not prose:

| Tool | Answers | Refuses when |
| --- | --- | --- |
| `versionStatus(version)` | state, open counts, upgrade target, scanned date | the version was never measured, naming the nearest that was |
| `cveStatus(id, version?)` | the verdict, fix coverage per line, or for one version | the id is unknown to the measurements |
| `upgradeTarget(version)` | what the newest release of the line clears and what remains | same as versionStatus |
| `openFindings(version)` | the risk and triage lists with one line each | same |
| `queueHead(n)` | the top of the verdict queue | n out of range |

The 25.4 `ToolCallLimitExceededException` is handled as a user visible sentence, the assistant gave up after N tool calls, never as a stack trace. Tool results are kept compact by the tools themselves, `openFindings` paging through its own offset and limit, at most 25 lines; `QueryPage` is not used for them, D-143, and appears only where the Grid AI controller pages its query.

### Attachments

A photographed or screenshotted scanner line can be attached, through an upload button at the start of the composer, on an `UploadManager` the orchestrator takes as its file receiver, with `UploadCapture.ENVIRONMENT` offering the back camera on a phone and one image of at most 5 MB, D-256; the message input has no attachment slot of its own. The model extracts the advisory id and coordinate, then must call `cveStatus` like any other question: the image gives it the question, never the answer.

### History

Conversation history persists per session through the 25.3 history API, so leaving the explorer and coming back keeps the exchange. Text only, attachments are not replayed.

## Limits

Per session, at most 30 prompts in 10 minutes across the chat, the advisory ask and the verdict fill, refused in words through the request interceptor. The history keeps its last 40 messages. The model writes at most 2 000 tokens a turn, `spring.ai.openai.chat.options.max-completion-tokens`, D-260.

## Form AI

The workbench verdict form takes a paste: the prose of a security report, an email, a GHSA description. The Form AI controller fills the draft fields from it, field markers show what the model filled, and the human edits before anything is saved. The controller never submits: filling and saving are two acts, and only a person does the second.

## Grid AI

The advisories grid on `/advisories` takes a plain language ask, show the critical ones still open on 24.9, through the Grid AI controller with query validation on. Same grid, same data provider, the controller only narrows it. The ask box shows only to the `SECURITY` role, on `/advisories` and `/findings/advisories`, and only when the assistant is offered, D-141, D-236.

## Prompt contracts

System prompts live in `src/main/resources/prompts/`, one file each, `assistant.md`, `grid.md`, `form.md` and `catalogue-schema.md`, with the tool descriptions, schemas and refusal sentences in `tools.json`, D-147, under test as text: a cassette asserts the prompt that shipped is the prompt the cassette was recorded against, so a prompt edit that silently invalidates every recording fails the build instead.

The contracts, in one line each: the assistant answers only from tool results and says "the measurements do not say" when they do not; the form filler fills only fields the text supports and leaves the rest empty, rule 4 again; the grid controller emits only filters, never data.

## What a test can prove

- With cassettes: that a question produces the expected tool calls, that a tool refusal is relayed and corrected from, that the answer quotes the tool result and not training data, that limits surface as sentences. Deterministic, in the gate.
- With a live model, `-Pai` and the empty excluded groups, tagged `live-ai`: that the real provider wires up, that one canonical question lands end to end. Evidence, not proof, one rerun in CI, never in the gate.
- Never: wording assertions against a live model.
