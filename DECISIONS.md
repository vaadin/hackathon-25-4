# Decisions taken without asking

The implementation pass runs unattended. Whenever a choice was needed and nobody was there to make it, the best guess was taken and written here, so each one can be confirmed or reverted afterwards. One row per decision, numbered and never renumbered. A reverted decision keeps its row and says so.

| # | Epic | Decision | Why | The alternative | To revert |
| --- | --- | --- | --- | --- | --- |
| D-01 | 01 | `anyRequest(permitAll)` on the security configurer | With the default deny all, an unknown address sends an anonymous reader to the login page and a signed in one to a bare 403, where the feature asks for Flow's not found view | Keep deny all, the framework's design | Remove the `.anyRequest(...)` line in `base/security/SecurityConfig.java`. As it stands, any endpoint that is not a Vaadin view is open unless it gets a rule |
| D-02 | 01 | Our own enforced Content Security Policy with `'unsafe-inline'` and `'unsafe-eval'`, and `vaadin.csp=warn` | The 25.4 strict mode sends nothing in development and covers only the bootstrap page, and the spec wants every later epic developed under the policy | `vaadin.csp=strict` with no policy of ours | Delete `CspPolicy`, `CspOnBootstrapPage` and the `headers(...)` call, set `vaadin.csp=strict` |
| D-03 | 01 | The internal drawer lists only routes that exist, built from `@Menu` | A link to a route that does not exist yet would be an invention | List the four destinations the feature names from the start | Replace the `MenuConfiguration` loop in `InternalLayout` with fixed items |
| D-04 | 01 | No custom access denied view | Not asked for by the story. A signed in user without the role sees the not found view, which is the documented default | The documented `HasErrorParameter<AccessDeniedException>` view saying "not allowed" | Add the view in `base/ui` |
| D-05 | 01 | Partial stylesheets live in `/styles/` behind a permit rule | Chosen before knowing that `/assets/**` and `/themes/**` are public by default | Move them under `/assets/` and delete the rule | Move the folder, change the `@import`, drop the matcher in `SecurityConfig` |
| D-06 | 01 | No session limit, so `VaadinExpiredSessionStrategy` is installed and idle | The two demo accounts are shared by several people | `maximumSessions(n)` so the 25.4 strategy is live | Add `sessionManagement(...)` in `SecurityConfig` |
| D-07 | 01 | The trail reads Vaadin, Security status, leaf | The feature document says so | Add "My account", as the live page has | One more item in `AppBar.showTrail` |
| D-08 | 01 | Breadcrumbs in `MANUAL` mode, rebuilt from the route hierarchy | `ROUTER` mode cannot carry the leading Vaadin item, which is not a route | `ROUTER` mode without the Vaadin item | Replace `showTrail` with `new Breadcrumbs()` |
| D-09 | 01 | Placeholder `HomeView` and `ExplorerView` with only a heading | A shell needs a route to render and a boundary needs a route to guard | None. Epics 03 and 08 fill them | Not applicable |
| D-10 | 01 | The measured chip reads "Measured" plus an ISO date in UTC | Matches the header of the live page. Epic 02 owns the final wording | Another format or wording | `shell.measured` in the bundle and `MEASURED_DATE` in `AppBar` |
| D-11 | 01 | Base font 16px and heading 28px | The review measured 14px against the reference's 16px | Aura's defaults | `--aura-base-font-size` in `styles.css`, `.view-heading` in `styles/shell.css` |
| D-12 | 01 | Sign out is in the shared app bar for any signed in session | A signed in `guest`, refused on the internal area, had no way out | Sign out only in the internal shell | Move the button from `AppBar` to `InternalLayout` |
| D-13 | 01 | `SpecConsistencyTest` enforces a table only once the story or the feature is fully ticked | Enforcing all 82 rows from epic 01 would fail the build until epic 13 | Enforce nothing until the end | The two `allTicked` conditions in the test |
| D-14 | 01 | `NoHardcodedStringsTest` treats two words, or one capitalised word, as wording, and exempts lines that log, throw or declare JavaScript | A rule strict enough to catch a label and loose enough to pass keys and tokens | A parser based check of what reaches a component | The patterns at the top of the test |
| D-15 | 01 | The dev loop tooling the installer wrote, `.vaadin/`, `.agents/` and `.claude/skills/vaadin-devloop`, is committed | The installer says the scripts are project tooling | Leave them untracked | `git rm` them |
| D-16 | 01 | `src/main/bundles/` is ignored | It is generated on start, 2.7 MB, and left untracked it makes the posting script refuse | Commit it, which speeds up a cold start | Remove the line from `.gitignore` |
| D-17 | all | No issue or comment is posted and `post.sh --confirm` is never run | The issues are reviewed and accepted one by one after the hackathon | None | Not applicable |
| D-18 | all | Each remaining epic is implemented by its own unattended session, driven by `.claude/commands/implement-epic.md`, one after another | The overview schedules one unattended session per epic, and the epics depend on each other and share one working tree and one port | One long session for everything | Delete the command file. It changes nothing in the product |
| D-19 | 02 | An empty text in the JSON is absent in the read model, the same as a null or a missing field | The pipeline writes `"workaround": ""` where it has nothing to say, and AC4 asks that absent never maps to an empty string. Rendering an empty row for it would be the invention rule 4 forbids | Keep `""` as a present, empty value and leave every screen to test for it | `Wire.text` in `data/model/Wire.java`, one filter |
| D-20 | 02 | Numbers and flags are nullable boxes, lists and maps are empty when absent, texts and nested objects are `Optional` | A missing count mapped to `0` would read as "nothing found", which is a claim. An absent list has nothing to render either way | `Optional` everywhere, or primitives with defaults | The record components in `data/model/` |
| D-21 | 02 | Where the specification describes the JSON differently from what the live site sends, the records follow the site: `summary` buckets are counts and not id lists, a line's `kind` is `ga` or `prerelease` and not `release`, `fix_expected_version` is an object nobody has filled yet and is kept as a map | The field lists were captured again from live fetches on 2026-11-20 and the records map what arrived. The specification is not edited | Model what `02-data-source.md` says and fail on the fixtures | Not applicable, the fixtures decide |
| D-22 | 02 | The committed fixture set is eighteen files, 1.9 MB: every endpoint shape once, three version documents for the three states, three advisories, and the five export files of 25.3.5. `data/queue.json` alone is 923 KB | One fixture per endpoint shape is what `02-data-source.md` asks, and a truncated queue would not be a pinned copy of a real answer | A smaller set with the big documents cut by hand, which the same document forbids | The `PATHS` list in `scripts/refresh-fixtures.sh` |
| D-23 | 02 | Tests reach the fixtures through a transport bean, `FixtureTransport`, that a test configuration in the application package puts in place of the network. The client, the cache and the mapper are the production ones | The application has no offline mode by decision, so nothing in `src/main` knows about fixtures. The only seam is the request factory `PagesClient` is built with | A `classpath:` base address understood by `PagesClient`, which would be an offline mode | `FixturePages` and `FixtureTransport` in `src/test/java/.../data/`, the `pagesTransport` qualifier in `DataConfiguration` |
| D-24 | 02 | Under `-Pit` the application is started with `securitystatus.pages.base-url` pointing at `localhost:8082`, and the browser tests serve the fixtures there with a JDK `HttpServer`, `FixturePagesServer` | The application under test is a separate process in production mode with no test classes on its classpath, and the gate must not need the network. A real HTTP host also makes `ExportsProxyIT` prove the streaming across two real connections | Start the application with the test classpath, or let the browser tier fetch from GitHub Pages | The `it.pages.port` property and the argument in the `it` profile of `pom.xml`, and the `@ExtendWith` on the three `*IT` |
| D-25 | 02 | The architecture test is a scan of the import statements in `src/main/java`, `NetworkBoundaryTest`, with a planted control. No ArchUnit | It needs no dependency, it is the pattern `NoHardcodedStringsTest` already set, and the client and the cache are package private so the compiler holds the rest | Add ArchUnit and check dependencies in bytecode, which would also catch a fully qualified name with no import | Delete the test, add the dependency and a rule |
| D-26 | 02 | The home view shows a skeletal card per followed line, the minor and its newest measured release, with prerelease lines left out, redrawn when the refresh signal moves | US-2.3 asks for home cards bound to the signal and DAT-04 needs a view that reads the data. | D-27 | 02 | The placeholder explorer view lists, per line, five download links for the machine files of its newest release, whether or not the publisher has every one of them | `ExportsProxyIT` needs a real download link to fetch, and a `Download` handler has no address until a component owns it. | D-28 | 02 | The unreachable sentence is ours: "The security data cannot be reached right now, so there is nothing to show here yet." | The source pages are static and never had this state, so `docs/requirements.md` has no wording for it | Another sentence | `data.unreachable` in the bundle |
| D-29 | 02 | The measured chip keeps the wording of D-10, "Measured" and the ISO date of `generated_at` in UTC. A stale answer is told apart only by that date | It matches the live header, and `02-data-source.md` says staleness is surfaced once, as the data's own `generated_at` | Add the time, or a word such as "stale" when the last refresh failed | `shell.measured` in the bundle, `MEASURED_DATE` in `AppBar` |
| D-30 | 02 | When `generated_at` moves, the other cached documents become due for revalidation and are not dropped. After a failed refresh a stale entry answers for one minute before the publisher is asked again | Dropping them would lose the stale answer if the publisher then went down, against stale over error. Without the minute every read of a stale entry would wait for a timeout | Drop on move, and retry on every read | `PagesCache.expireAllExcept` and `RETRY_AFTER_FAILURE` |
| D-31 | 02 | Only the index has the 15 minute time to live. Every other document, the front, the queue, the scan index and the case catalogue included, has six hours and is made due by a moved index | `02-data-source.md` names 15 minutes for the index and six hours for the per version and per CVE documents, and says a new `generated_at` invalidates everything else | 15 minutes for every document that carries its own `generated_at` | The two constants in `SecurityDataService` |
| D-32 | 02 | A version or an advisory id that is not made of letters, digits, dots, dashes and underscores is answered empty without a request | Both come from the address a reader typed, and they become part of the path asked of the publisher | Encode whatever arrives and let the publisher answer 404 | `PATH_SEGMENT` in `SecurityDataService` |
| D-33 | 02 | The cache is warmed when the application is ready, on the starting thread, and the scheduled revalidation runs every 15 minutes from then on, both configurable | The risk register asks for a warm cache before the demo, and a synchronous warm keeps the tests deterministic. A dead publisher costs the start one connect timeout of five seconds | Warm on a background thread, or on the first read | `DataConfiguration.warmTheCache`, `securitystatus.pages.revalidate-every` |
| D-34 | 02 | A `Clock` bean lives in `data/DataConfiguration`, and the test configuration overrides it with a fixed one marked primary | `08-testing.md` says the clock is fixed in the test profile, and the cache is the first thing that reads time | A clock per class | Move the bean to `base` when a second package needs it |
| D-35 | all | Whatever only a person can do is moved to the end and listed in `NEEDS-A-PERSON.md`. Epics 12 and 13 no longer wait for the interactive polish the overview puts between epics 11 and 12 | The person asked for the whole implementation unattended, with their own part at the end | Stop at the first such thing | Follow the schedule in `specs/00-overview.md` |
| D-36 | 02 | A reader who finds a moved index publishes the new `generated_at` after its own request is over, through `VaadinSession.access`, and not at once | At once is inside the effect that depends on the signal, which Flow forbids. From another thread it was lost for the component being built, the finding in draft 11 | Publish only from the scheduled task, and let the first reader after a cold start wait for it | `DataConfiguration.afterTheCurrentRequest` |
