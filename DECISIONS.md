# Decisions taken without asking

The implementation pass runs unattended. Whenever a choice was needed and nobody was there to make it, the best guess was taken and written here, so each one can be confirmed or reverted afterwards. One row per decision, numbered and never renumbered. A reverted decision keeps its row and says so.

| # | Epic | Decision | Why | The alternative | To revert |
| --- | --- | --- | --- | --- | --- |
| D-01 | 01 | `anyRequest(permitAll)` on the security configurer | With the default deny all, an unknown address sends an anonymous reader to the login page and a signed in one to a bare 403, where the feature asks for Flow's not found view | Keep deny all, the framework's design | Remove the `.anyRequest(...)` line in `base/security/SecurityConfig.java`. As it stands, any endpoint that is not a Vaadin view is open unless it gets a rule |
| D-02 | 01 | Our own enforced Content Security Policy with `'unsafe-inline'` and `'unsafe-eval'`, and `vaadin.csp=warn` | The 25.4 strict mode sends nothing in development and covers only the bootstrap page, and the spec wants every later epic developed under the policy | `vaadin.csp=strict` with no policy of ours | Delete `CspPolicy`, `CspOnBootstrapPage` and the `headers(...)` call, set `vaadin.csp=strict` |
| D-03 | 01 | The internal drawer lists only routes that exist, built from `@Menu` | A link to a route that does not exist yet would be an invention | List the four destinations the feature names from the start | Replace the `MenuConfiguration` loop in `InternalLayout` with fixed items |
| D-04 | 01 | No custom access denied view | Not asked for by the story. A signed in user without the role sees the not found view, which is the documented default | The documented `HasErrorParameter<AccessDeniedException>` view saying "not allowed" | Add the view in `base/ui` |
| D-05 | 01 | Partial stylesheets live in `/styles/` behind a permit rule | Chosen before knowing that `/assets/**` and `/themes/**` are public by default | Move them under `/assets/` and delete the rule | Move the folder, change the `@import`, drop the matcher in `SecurityConfig` |
| D-06 | 01 | No session limit, so `VaadinExpiredSessionStrategy` is installed and idle | The two demo accounts are shared by several people | `maximumSessions(n)` so the 25.4 strategy is live | Add `sessionManagement(...)` in `SecurityConfig` |
| D-07 | 01 | The trail reads Vaadin, Security status, leaf | The feature document says so | Add "My account", as the live page has | One more item in `AppBar.showTrail` |
| D-08 | 01 | Breadcrumbs in `MANUAL` mode, rebuilt from the route hierarchy | `ROUTER` mode cannot carry the leading Vaadin item, which is not a route | `ROUTER` mode without the Vaadin item | Replace `showTrail` with `new Breadcrumbs()` |
| D-09 | 01 | Placeholder `HomeView` and `ExplorerView` with only a heading | A shell needs a route to render and a boundary needs a route to guard | None. Epics 03 and 08 fill them | Not applicable |
| D-10 | 01 | The measured chip reads "Measured" plus an ISO date in UTC | Matches the header of the live page. Epic 02 owns the final wording | Another format or wording | `shell.measured` in the bundle and `MEASURED_DATE` in `AppBar` |
| D-11 | 01 | Base font 16px and heading 28px | The review measured 14px against the reference's 16px | Aura's defaults | `--aura-base-font-size` in `styles.css`, `.view-heading` in `styles/shell.css` |
| D-12 | 01 | Sign out is in the shared app bar for any signed in session | A signed in `guest`, refused on the internal area, had no way out | Sign out only in the internal shell | Move the button from `AppBar` to `InternalLayout` |
| D-13 | 01 | `SpecConsistencyTest` enforces a table only once the story or the feature is fully ticked | Enforcing all 82 rows from epic 01 would fail the build until epic 13 | Enforce nothing until the end | The two `allTicked` conditions in the test |
| D-14 | 01 | `NoHardcodedStringsTest` treats two words, or one capitalised word, as wording, and exempts lines that log, throw or declare JavaScript | A rule strict enough to catch a label and loose enough to pass keys and tokens | A parser based check of what reaches a component | The patterns at the top of the test |
| D-15 | 01 | The dev loop tooling the installer wrote, `.vaadin/`, `.agents/` and `.claude/skills/vaadin-devloop`, is committed | The installer says the scripts are project tooling | Leave them untracked | `git rm` them |
| D-16 | 01 | `src/main/bundles/` is ignored | It is generated on start, 2.7 MB, and left untracked it makes the posting script refuse | Commit it, which speeds up a cold start | Remove the line from `.gitignore` |
| D-17 | all | No issue or comment is posted and `post.sh --confirm` is never run | The issues are reviewed and accepted one by one after the hackathon | None | Not applicable |
| D-18 | all | Each remaining epic is implemented by its own unattended session, driven by `.claude/commands/implement-epic.md`, one after another | The overview schedules one unattended session per epic, and the epics depend on each other and share one working tree and one port | One long session for everything | Delete the command file. It changes nothing in the product |
