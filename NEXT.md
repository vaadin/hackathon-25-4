Traps learned in these sessions:

- The CVE screen shares the version screen's classes, `version-body`, `verdict-card`, `verdict-state`, `section-row`: a rule meant for one of them goes under `.version-view` or `.cve-view`. Since D-186 the tinted card rules in `styles/version.css` are scoped to `:is(.version-view, .cve-view)`; checked in a browser on both screens.
- A version document's assessments carry no `commentary`; the advisory document's copy of the same assessment id does, D-196. Survey both copies before calling a field absent.
- The index's `labels` has no `not_current`; the bundle's `verdict.label.not_current` is the prototype's word for it, `AdvisoryRules.label`.
- GitHub Pages answers a missing path with 503 now and then instead of 404; the client asks once more, D-190. An unknown id that still shows the outage notice is that.
- An address whose ids do not parse, such as a GHSA with letters a GHSA never uses, shows the H2 and nothing under it; the prototype says "not in anything we scanned". Not changed, only a hand typed address reaches it.
- A bundle key read without arguments is not passed through `MessageFormat`, so its apostrophe is written once; a key read with arguments doubles it. `version.disc.fix` is the first kind, `version.boot.commercial` the second.
- The prototype marks what it cannot show with `.missing` and `.cannot` elements whose `title` says why. Read them before calling a prototype datum a data gap: they are its own data need list.
- The prototype reads a report in the browser: Playwright's `setInputFiles('#report-file', ...)` uploads to it, and its CSV is a blob, caught by wrapping `URL.createObjectURL` before the click. The application's file input is in the shadow root of `vaadin-upload-button`, which Playwright's locator pierces. Upload from the repository's `src/test/resources/scan/`.
- The report panel is `display: contents` so the version field, the Check button and the card share the fields' row, ordered by CSS `order`; the rule is guarded by `:not([hidden])`, or the hidden panel would show on the other tabs. `innerText` follows the DOM order, not the visual one, so the Answer button reads after the sentence in a text diff.
- Compare a screen by its whole `innerText` on both sides, the prototype's `main` after the lookup's tip and the app's view root, for each state; the line by line diff finds every wording difference at once.

- The prototype's internal page reads its rules from `web/findings/answer.js` of vaadin/cve-status, a file without DOM written to be tested: read it before calling a number of the prototype wrong. Its products sit in the hash, `#name` turning on and `#-name` turning off against the default, and the search and the opened series in the query, replaced in place.
- The prototype remembers its products in local storage under `cve.uses` and restores them when the hash is empty, so a state compared after a click carries over to the next address: clear its storage between states.
- A control that changes the explorer's products must write its selection into the address even when it is the default, `ExplorerView.address(..., true)`, or the remembered selection is restored over a bare address the reader just asked for. The view then writes the default away.
- A component hidden with `setVisible(false)` sends no children to the browser: the assistant panel's message input exists in the DOM only once the Assistant button has opened it, and a browserless query finds it only then.
- The internal bar carries the H1, four destination links, the trail, the chip, the switch, Assistant and Sign out: below about 1500 pixels it has to wrap, `::part(navbar)` with `flex-wrap: wrap`, or Sign out is pushed off a laptop's screen, which `CspIT` at 1280 caught.
- The App Layout's drawer must not be opened from the server on first arrival: the server cannot know the window is narrow, and an overlay drawer opened that way covers the toggle. `InternalLayout` opens it again only after a route without a panel shut it.

- The person's own instance of the application runs on 8080 and holds the H2 drafts file `~/.security-status/drafts.mv.db` locked; a second instance fails to start on it. Run a second one with `PORT=8090 SECURITYSTATUS_DRAFTS_DIR=<scratch dir>`.
- At 390 pixels the Breadcrumbs fold My account and Security status into their overflow menu, so a test that clicks My account needs a wide window.
- The web component value of the version combo box is the item key, `"1"`, not the version: read the text of its `input` in a browser check.

- A release record carries no `needs_spring`, only the front door's line does; the prototype's release page reads the record alone and so rings a Spring borne finding through every product on its route. `ReleaseRules.asLine` passes no `needs_spring` on purpose, D-216: with the line's list the chips read 16 where the prototype reads 42.
- A record's findings carry no `ecosystem`; `ReleaseRules.ecosystem` reads a frontend finding from its packages, a coordinate without a group, which is the prototype's test. Without it the frontend sentence said "could not trace".
- `{0,choice,1#...|1<...}` formats 0 with the first branch, "1 advisory": a count that can be nought needs a `0#` branch.
- A properties value written through a shell heredoc lost its `\u0020` escapes and the leading space with them; check the bytes of a join key such as `workbench.said.and`.
- The Aura checkbox's label covers its input: a Playwright click goes on `vaadin-checkbox label`, not on the `input`.
- The workbench has one form; it moves into the row opened and back to the fold at the foot of the page when the row shuts. A browserless test opens a row with `WorkbenchView.open(name)`; the queue is no grid any more.
- `ExplorerRules.Group`, `grouped`, `vaadinBadge` are no longer used by the screens, only by `ExplorerRulesTest` and, for `springBadge`, the Spring Boot page; they can go with their tests.

## Known traps

- `src/main/bundles/prod.bundle` is reused by a production build whenever the scanned imports are all in it, even when a route is new: a route that brings no new import gets no `loadOnDemand` key, and landing on it in production leaves its layout's components undefined. Since epic 13 the `it` and `production` profiles set `forceProductionBuild` and the log says `Frontend build requested.`, D-156; any other production build, or a jar built without those profiles, still has the trap, and the log line `A production mode bundle build is not needed` is its sign. Draft 23b, flow#26338. The file is ignored by `.gitignore` here.
- Navigation events fire in browserless tests too, so `DiagnosticsCounters` moves during every test class that navigates; the context is shared, so diagnostics tests assert on differences, never on absolute counts.
- A refused navigation, a guest on an internal route, ends as `Failed` with the not found view, and a 404 likewise: the outcome cannot tell them apart.
- `getTranslation` with an `int` argument formats it with grouping, `1,200`; pass numbers that are not quantities as strings.
- A browser window resize reaches the server about a second after the resize, so a check right after `browser_resize` still sees the old size.
- In a browserless test the end of an AI turn, the response listener, the controller's `onResponse` and the field markers, is a `UI.access` task that runs at the next component query. Query a component before asserting on anything the turn changes, and in an Awaitility condition put the query first, or the wait never ends.
- The orchestrator trims the system prompt before it sends it. A hash of the file as read differs by the final newline.
- The Grid AI controller probes a query through `executeQuery(String, QueryPage)` and pages through the default implementation, which wraps the query in a subquery: column metadata is only the model's own on the raw query, so `AdvisoryCatalogue.requireAdvisoryFirst` runs it once on its own.
- An H2 setting in the address, `;DB_CLOSE_DELAY=-1`, needs admin rights: the read only user connects by the bare name.
- Every writable field gets a `vaadin-ai-field-marker` child while a fill runs; only the changed ones keep it when the turn ends.
- `surefire.excludedGroups` was never read until D-148: Surefire's property is `excludedGroups`, and the pom now hands it over.
- The AI components reached through the `AiSurfaces` bean were missing from the production bundle, the trap of D-79 again, D-149. A new component a surface uses needs a `@Uses` on `InternalLayout` or on the route.
- Against the live model a turn takes 20 to 25 seconds. A Playwright wait for the answer needs that long.
- Spring AI's OpenAI starter reads the key from `OPENAI_API_KEY` by itself; nothing in `application.properties` names it.

- In the Playwright browser of this machine real clicks stopped reaching the page after a sign in, even after a click on an empty area and a fresh browser: no `pointerdown` reached the document at all. A new tab in an isolated context, `browser_tabs` with `isolatedContext`, signed in by typing, took real clicks from the first one. Epic 10 was verified that way, with real clicks.
- `key` is a reserved word in H2: an entity field named `key` fails the table creation with only a warning in the log, and every query after it. The draft's identity is `draftKey`.
- Flow does not send the attributes of an invisible component, its class names included, until it is shown: a hidden paragraph is a bare `<p hidden>` in the browser. Query by class after it is shown.
- The workbench drives its YAML through a `ValueSignal` that the binder's value change listener writes, rather than reading fields inside an effect.
- In auto responsive mode a `FormLayout` keeps its fields at the column width, about 12em, whatever `setWidthFull` says, until `setExpandColumns(true)` and `setExpandFields(true)` are set. Labels stay aside only while the layout is wider than the label width plus the column width: with 11em and 20em they fell above the fields at a 1200 pixel window, so the form uses 10em and 16em.
- A form GET sends every line break as CR LF. What GitHub's editor does with that is P-17.
- `vaadin/docs#6625` documents `NativeForm`; until it lands the javadoc is the only reference.
- A view that renders hundreds of rows at once, the Spring Boot page with its risk folds open, paints slowly: a Playwright viewport screenshot taken right after navigation came back blank while the DOM was complete. Wait, or fold, before screenshotting.
- A component that a test reaches through `Details.getContent()` must be the direct child, not wrapped in a `Composite`: `FindingGrid` extends `Grid` for that reason, the explorer tests filter the folds' children by `Grid.class`.
- Spring Boot advice has two "nothing newer" cases: no newer patch of the line, while a later minor may exist, and nothing newer in the major. Saying "within this major" while naming a later minor contradicts itself, which the review caught.
- After a production sign in in Playwright the Enter key and the first click on Sign in did nothing; the second click signed in. The same Chrome password bubble trap as before.

- `RouteParameters.getParameterNames()` is a set. `TranslatedPageTitleGenerator` now orders the parameters by the route template, D-106; anything else that numbers route parameters has to do the same.
- `ExplorerVersion.PackageFinding.declared` is a list of objects, D-105. The 25.3.5 fixture carries it null; 24.9.21 now carries it filled, so `ReleaseViewBrowserlessTest` reads the published shape. Survey the live documents' field types when a model is first used for real.
- `GridTester.clickRow` does not open a row's item details, browserless-test#29, draft 20b. Open them with `grid.setDetailsVisible(item, true)` in the test; a query then finds the details component.
- A filter control that navigates adds a history entry per change, D-98. `History.replaceState(state, location, true)` is documented for the React router and was not tried.
- In epic 08 mouse clicks did not reach the page in the Playwright browser. In epic 09 real clicks worked once one click on an empty area after the sign in had been spent: the save password bubble, as `specs/issues/README.md` says. Epic 09 was verified with real clicks.
- `lsof -ti :8080 | xargs kill` also kills the browser processes that hold a connection to 8080. Stop the application by its listening port only, `kill $(lsof -nP -tiTCP:8080 -sTCP:LISTEN)`.

- `./mvnw verify -Pit` runs the application in production mode, `./mvnw` in development mode. A browser test that passes against one and fails against the other is telling you they differ.

- A local `ValueSignal` in an application scoped bean throws when a second session reads it. Shared state uses `SharedValueSignal`, and a browserless test calls `runPendingSignalsTasks()` after changing one.
- The return to the asked route is proven in `ShellSecurityBrowserlessTest` by posting the sign in on the session of the refused navigation.
- `@RouteParent` is the logical hierarchy for the trail, not the rendering layout.
- `./mvnw` has no hot reload. Restart after a Java change, `./mvnw process-resources` after a CSS change, `VAADIN_LAUNCH_BROWSER=false` to keep the browser closed. The dev loop is installed and measured in `specs/10-dev-loop.md`. Never run both.

- The live reference pages show a sign in gate, so the visual reviews compared only the gate and the header behind it.
- Signals refuse `get()` outside a reactive context. In a listener, a click handler or a navigation observer read them with `peek()`; `get()` belongs in `Signal.effect`, `Signal.computed` and the `bind*` lambdas.
- An effect may not write a signal it depends on. A listener that a server side change also fires, such as the selected change of `Tabs`, writes only when the value differs, as `Lookup` does.
- `Button.bindEnabled` is refused beside `setDisableOnClick`, in either order, `UNTIL_RESPONSE` too. Use `Signal.effect` with `setEnabled`, draft 13.
- `ComboBox.setPartialMatchMode` throws once custom values are allowed, as its documentation says.
- A combo box's typed text is not its value. Read it through the `filter` property with a `filter-changed` listener, and empty it with the component's own `clear()`.
- JavaScript aimed at an element that is invisible waits until it is shown, documented on the calling JavaScript page. Run it from a visible ancestor, passing the element as a parameter.
- A combo box dropdown left open on a field that gets hidden covers the page when the field is shown again. Close it on every tab change.
- Queries in browserless tests return only visible components. A field of a hidden tab is reached by walking the tree, as `LookupBrowserlessTest.inLookup` does.
- A browserless window opens on home before the test body runs, so navigating to home again reuses that view. Leave and come back to rebuild it.
- `FixturePages.cold()` moves the refresh signal, and an open view reads the index again at once. Replace a fixture after `cold()` and then call `revalidate()`, or the committed one is cached first.
- A keyboard filter is browser JavaScript, so a browserless test proves only the server half: it fires the event with `"@" + filter.getSnippetKey()` set to what the browser would have returned. The browser half is checked with Playwright.
- The first page load after adding a component or a `@JsDefinition` rebuilds the development bundle, about ten seconds.
- A refresh of the fixtures moves every date the tests assert on. `FixturePages.PINNED_GENERATED_AT`, `FixturePages.NOW` and the literals in the data and home tests move with it, as they did in D-50.
- A component built inside one effect and holding a binding or effect of its own is tracked on its own: toggling a flag that only a section link reads does not redraw the sections around it. `VersionViewBrowserlessTest` asserts the same instances survive.
- A link drawn once and kept while other flags move must read the address when clicked, not when drawn. `VersionView.sectionLink` keeps its `href` in step through the `shown` signal.
- `QueryParameters` writes parameters in hash order, whatever order they were built or parsed in, draft 14. Compare addresses as maps in tests, `VersionViewBrowserlessTest.assertAddress`.
- A browserless test that fires a DOM event at a listener with a declared filter must answer the filter itself, `"@" + filter.getSnippetKey()` set to true, and goes through `ElementListenerMap`, because the testers' `fireDomEvent` is protected. The documentation recommends routing intent through a public method instead.

A small reproducer did not show it, so it is not a finding.
